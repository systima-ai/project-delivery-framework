# Call-debrief guide

Rubrics, rating scale, and output format for `pdf-debrief-call`.

---

## Rating scale

Default **1–10** per dimension (configurable in `customize.toml`). The scale is not a grade to be inflated; it is a signal. Anchor it:

- **9–10** — exceptional; nothing material to improve on this dimension.
- **7–8** — strong; minor refinements only.
- **5–6** — adequate; clear gaps.
- **3–4** — weak; a real problem.
- **1–2** — failed on this dimension.

Every score carries a **one-line evidence note** citing the call (a quote, a moment, a behaviour). A score with no evidence is not allowed.

---

## Dimension rubrics by call type

Pick the rubric matching the call type the user names. These are starting sets; adapt a dimension if the call clearly needs it, but keep the spirit (objective, evidenced).

### Discovery / pre-contract call
- **Rapport** — did a working relationship start?
- **Qualification signal** — what did we learn about fit, budget, authority, need, timing?
- **Pain surfaced** — did the real problem get named?
- **Credibility established** — did we earn the right to the next conversation?
- **Questions asked** — did we interrogate, or just pitch?
- **Next-step secured** — is there a concrete, owned next action?

### Stakeholder / steering call
- **Message landed** — did the key message get received as intended?
- **Objections surfaced** — did real concerns come out, or stay hidden?
- **Alignment** — are we more or less aligned after the call?
- **Trust** — did this build or spend trust?
- **Actions agreed** — concrete, owned, dated?

### Negotiation / commercial call
- **Position clarity** — is each side's position now explicit?
- **Interests vs positions** — did underlying interests surface?
- **Concessions** — what moved, by whom, for what?
- **BATNA awareness** — do we understand the walk-away on both sides?
- **Next-step secured** — what's committed and by when?

### Interview / assessment call
- **Relevant evidence** — were claims backed by specific, relevant experience?
- **Domain credibility** — depth where it matters for the role/task?
- **Communication** — clear, concise, audience-aware?
- **Questions asked** — curiosity and judgement, not just answers?
- **Risk/doubt handling** — were the obvious concerns addressed?
- **Outcome confidence** — how strongly does the evidence support a yes?

### Other
Use a small set of dimensions you can defend, each scored and evidenced. State the rubric you chose in the file.

## Output format

```markdown
---
artifact_type: call-debrief
engagement: <slug>
date: <YYYY-MM-DD>
call_type: <discovery | stakeholder | negotiation | interview | other>
source: <transcript path | notes | recollection>
generated_by: pdf-debrief-call
confidential: <true | false>
---

# Call debrief — <call label> — <date>

## Outcome

<Plain statement: what happened and what it means for next steps. This leads.>

**Overall:** <one-line verdict, e.g. "Strong — advanced to next stage" / "Mixed — alignment slipped on scope">

## Ratings

| Dimension | Score | Evidence |
|---|:--:|---|
| <dimension> | <n>/<max> | <one line citing the call> |
| ... | | |

## What went well

- <specific, evidenced>

## Where it was weaker

- <specific, evidenced>  ← at least one; mandatory

## Intelligence captured

- <durable fact: named people + roles, structure, constraints, tooling, commercial signal, risk>
- <unconfirmed item> [?]

## Follow-ups

- [ ] <owner>: <action> — by <date if known>

---

*Generated by `pdf-debrief-call` from <source>. Internal after-action note.*
```

### Notes

- **Cumulative use (`update` intent):** for a counterpart you'll meet repeatedly, prepend each new dated debrief above the previous one so the relationship history lives in one file (same pattern as 1:1 prep).
- **Confidentiality:** set `confidential: true` when the debrief contains sensitive personal assessment; keep such files out of client-shareable outputs.
- **Consistency check:** if the narrative says "strong" but the scores are low (or vice versa), reconcile before writing — the validation intent flags this.
